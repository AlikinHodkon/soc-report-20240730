# Результаты расследования инцидента в ООО “Acme Corp”

## 1. Краткий обзор (Executive Summary)

30 июля 2024 года рабочая станция `DESKTOP-SKBR25F` (`172.16.1.66`), принадлежащая сотруднику Кларку Коллиеру, была скомпрометирована вредоносной программой **STRRAT версии 1.6** — трояном удалённого доступа, предоставляющим возможность удалённого управления компьютером и сбора сведений о действиях пользователя.

На момент начала записи сетевого трафика рабочая станция уже была скомпрометирована. С неё выполнялись запросы к службам Active Directory, направленные на получение сведений об учётных записях, группах пользователей и инфраструктуре сертификатов. Вскоре после этого было установлено постоянное соединение с внешним сервером управления (C2). Рабочая станция отправляла на него телеметрические сообщения с интервалом около 5 секунд, содержащие сведения о системе и текущей активности пользователя. Связь сохранялась на протяжении всего периода наблюдения (почти 10 минут) и оставалась активной в момент окончания захвата трафика.

Параллельно с работой вредоносной программы наблюдались признаки разведки корпоративной сети. Выполнялись запросы к контроллеру домена для получения информации о правах скомпрометированной учётной записи, членстве в группах и инфраструктуре сертификатов. Также зафиксированы операции с объектами Active Directory, связанные с изменением Service Principal Name (SPN). Совокупность этих действий указывает на вероятную попытку расширения доступа внутри доменной инфраструктуры и поиск возможностей для дальнейшего повышения привилегий.

Признаков успешного получения секретных данных домена, кражи конкретных файлов или шифрования данных в исследуемом трафике не обнаружено. Таким образом, наблюдаемая активность могла представлять собой подготовительный этап дальнейшего развития атаки, однако её конечные результаты по имеющимся данным установить невозможно.

Первоначальный вектор проникновения установить не удалось: компрометация рабочей станции произошла до начала записи сетевого трафика.

Период наблюдаемой активности: **30.07.2024, 05:38:48–05:48:34 (UTC+3)**. Технические сведения и доказательства, на основании которых сделаны выводы, приведены в разделе IOC.

### 3.3. Малварь: STRRAT v1.6

Название и версия вредоносной программы установлены непосредственно по содержимому C2-протокола, передаваемого в открытом виде.

Пример обнаруженного сообщения:

```text
ping|STRRAT|1BE8292C|DESKTOP-SKBR25F|ccollier|Microsoft Windows 11 Pro|64-bit|Windows Defender|<Base64>|1.6|US:United States|Not Installed|<аптайм>
```

Сообщение содержит название вредоносной программы, её версию, идентификатор заражённого клиента, имя компьютера, учётную запись пользователя, сведения об операционной системе и антивирусной защите.

Поле Base64 содержит закодированные названия активных окон пользователя. После декодирования получены следующие значения:

| Base64 | Расшифровка |
|---|---|
| `SG9tZQ==` | Home |
| `RG9jdW1lbnRz` | Documents |
| `UGljdHVyZXM=` | Pictures |
| `UHJvZ3JhbSBNYW5hZ2Vy` | Program Manager (рабочий стол) |
| `cG91bmRzLWZvcm11bGEg...UG93ZXJQb2ludA==` | pounds-formula [Compatibility Mode] - PowerPoint |
| `RmFuYWQg...UGFpbnQ=` | Fanad Head Lighthouse - Paint |

Таким образом, телеметрия STRRAT содержала сведения об активном окне пользователя: фиксировались переходы между каталогами проводника, работа с презентацией PowerPoint и изображением в Paint. Это подтверждает сбор сведений о текущей активности пользователя и согласуется с функциями мониторинга вредоносной программы.

### 3.4. Активность в Active Directory

С первых секунд записи зафиксированы обращения заражённой рабочей станции к службам Active Directory. Наблюдаемая активность включает несколько направлений разведки доменной инфраструктуры.

**Разведка инфраструктуры сертификатов**

Обнаружены LDAP-запросы к контейнеру Public Key Services, включая объекты Certificate Templates, Certification Authorities, AIA и OID.

Подобные запросы позволяют получить сведения об инфраструктуре Active Directory Certificate Services (AD CS), в том числе о шаблонах сертификатов и центрах сертификации. Сбор такой информации характерен для разведки перед возможной эксплуатацией уязвимых конфигураций AD CS, включая сценарии атак ESC1–ESC8.

**Взаимодействие с DRSUAPI и SAMR**

Также зафиксированы обращения к контроллеру домена по протоколу DRSUAPI, используемому механизмами репликации Active Directory, и запросы через SAMR.

В пакете № 1065, согласно разбору Wireshark, обнаружен SMB2 IOCTL-запрос к именованному каналу, содержащий вызовы SAMR, связанные с поиском учётной записи `ccollier` и получением сведений о её группах. Это свидетельствует о сборе информации о членстве пользователя в группах домена и его правах.

После установления C2-соединения частота обращений к DRSUAPI заметно увеличилась. Однако вызова `DRSGetNCChanges`, используемого для получения реплицируемых данных Active Directory, в исходном разборе Wireshark не обнаружено. Поэтому выполнение DCSync в исследуемом трафике не подтверждено. Наблюдаемая активность может свидетельствовать о разведке и подготовке к дальнейшим действиям с использованием механизмов репликации домена.

**Изменение Service Principal Name**

Особого внимания заслуживают DRSUAPI-вызовы `DsWriteAccountSpn`, зафиксированные в пакетах № 664 и 666. Эта операция предназначена для изменения Service Principal Name (SPN) объекта Active Directory.

Подобная операция может использоваться в сценарии targeted Kerberoasting: злоумышленник назначает SPN выбранной учётной записи, после чего может запросить Kerberos-билет для последующего офлайн-подбора пароля. Это делает обнаруженную активность более подозрительной и указывает на возможную попытку подготовки атаки на доменную учётную запись.

При этом сам факт вызова `DsWriteAccountSpn` не доказывает успешное изменение SPN или получение Kerberos-билета. Для подтверждения результата необходим анализ ответов сервера и последующих Kerberos-запросов.

**Проверка альтернативных сценариев атак на Active Directory**

Дополнительно проверены признаки двух распространённых атак на доменную инфраструктуру.

- **Kerberoasting** — в исследуемом трафике все обнаруженные запросы Kerberos-билетов используют AES256 (etype 18). Запросов с использованием RC4 (etype 23), характерного для некоторых сценариев Kerberoasting, не обнаружено. Однако использование AES256 само по себе не исключает Kerberoasting, поэтому полностью исключить эту атаку по одному сетевому дампу нельзя.
- **Zerologon (CVE-2020-1472)** — характерных признаков эксплуатации уязвимости Netlogon не обнаружено. Зафиксирован один вызов установки защищённого канала с ненулевыми параметрами, не указывающий на характерный массовый перебор. Вместе с тем отсутствие таких признаков в исследуемом захвате не позволяет полностью исключить эксплуатацию уязвимости за его пределами.

**Анализ HTTPS-соединений**

В TLS ClientHello соединений с GitHub и Maven Central обнаружена поддержка TLS не выше версии 1.2, тогда как обычный фоновый трафик исследуемой машины к Bing/MSN использовал TLS 1.3.

Различия в параметрах TLS-рукопожатий указывают на использование разных TLS-стеков или настроек соединения. Это позволяет предположить, что подключения выполнялись разными программными компонентами, однако не позволяет однозначно идентифицировать конкретный процесс или подтвердить связь этих соединений с STRRAT.

Совпадение по времени с появлением C2-соединения делает эти подключения заслуживающими внимания, но не является самостоятельным доказательством загрузки вредоносной программы.

### 3.5. Файловые индикаторы

SHA256-хеши файлов в отчёте не приводятся. Весь обнаруженный трафик передачи данных с GitHub, Maven Central и Oracle использовал TLS. Доступные материалы не содержат ключей сессий, необходимых для расшифровки передаваемого содержимого и извлечения исполняемых файлов.

### 3.6. Ограничения исследования

Расследование основано на анализе одного файла сетевого захвата `network.pcap`, что определяет следующие ограничения:

- первоначальный вектор проникновения установить не удалось: компрометация рабочей станции произошла до начала записи;
- содержимое HTTPS-соединений не может быть исследовано без ключей сессий;
- входящие команды от C2-сервера в исследуемом потоке не обнаружены: зафиксирована исходящая телеметрия, поэтому прямая связь между C2-каналом и выполнением запросов к Active Directory не установлена;
- факт вызова `DsWriteAccountSpn` не подтверждает успешное изменение SPN без анализа ответа сервера;
- доказательств успешного DCSync, кражи конкретных файлов или шифрования данных в исследуемом трафике не обнаружено.

Для установления событий, предшествовавших началу захвата, проверки закрепления вредоносной программы и определения фактических результатов атаки необходим дополнительный анализ дисковых образов и оперативной памяти скомпрометированной рабочей станции. Такие материалы в рамках настоящего исследования не предоставлялись.
